## 1. เกี่ยวกับแอป

ClaudeUsage คือวิดเจ็ตสำหรับเดสก์ท็อป Windows 11 ที่ช่วยให้เห็นภาพรวมการใช้งาน Claude ได้ในที่เดียว — จำนวนคำขอ (requests), โทเคน (tokens), ค่าใช้จ่ายโดยประมาณ, สัดส่วนการใช้งานแยกตามโมเดล และแนวโน้มการใช้งานย้อนหลัง ออกแบบตามแนวทาง Fluent Design ของ Windows 11 (พื้นผิว Mica, มุมโค้งมน, ฟอนต์ Segoe UI Variable) และทำงานเบาในพื้นหลัง

แอปมีสองโหมดข้อมูล:

- **Demo Mode** — แสดงข้อมูลตัวอย่างที่สมจริง โดยไม่ส่งคำขอเครือข่ายใดๆ เหมาะสำหรับทดลองใช้งาน (เปิดเป็นค่าเริ่มต้น)
- **โหมดเชื่อมต่อจริง** — ดึงข้อมูลจาก endpoint ที่คุณกำหนดเอง (ดูบทที่ 4)

> เวอร์ชันนี้ยังไม่มีไฟล์ติดตั้งสำเร็จรูปที่เซ็นใบรับรองสำหรับแจกจ่ายทั่วไป คู่มือนี้จึงอธิบายการติดตั้งจากซอร์สโค้ด

## 3. การติดตั้ง

### 3.1 วิธีที่แนะนำ — รันจาก Visual Studio

เร็วที่สุดสำหรับใช้งานบนเครื่องของคุณเอง — Visual Studio จะสร้างใบรับรองทดสอบและติดตั้งแพ็กเกจให้อัตโนมัติ

1. ติดตั้ง Visual Studio 2022 พร้อม workload `.NET desktop development` และ `Windows application development`
2. คัดลอกโฟลเดอร์ซอร์สโค้ดโปรเจกต์ `ClaudeUsage` มาไว้บนเครื่อง
3. เปิด `ClaudeUsage.sln` ด้วย Visual Studio แล้วรอให้ NuGet Restore เสร็จสิ้น
4. คลิกขวาที่โปรเจกต์ **ClaudeUsage** (ไม่ใช่ ClaudeUsage.Core) → **Set as Startup Project**
5. เลือก Configuration เป็น `Debug` และ Platform เป็น `x64` (หรือตามสถาปัตยกรรมเครื่อง)
6. กด **F5** เพื่อ build และรันแอป

> หากเป็นการรันแอปแบบแพ็กเกจครั้งแรกบนเครื่อง Windows อาจต้องเปิด **Developer Mode** ก่อน: *Settings → Privacy & security → For developers*

### 3.2 สำหรับแจกจ่าย — สร้างแพ็กเกจ MSIX

ใช้วิธีนี้เมื่อต้องการส่งไฟล์ติดตั้งให้ผู้อื่น เลือกได้สองแบบ — ผ่านหน้าต่าง Visual Studio (ทำครั้งเดียว ไม่ยุ่งยาก) หรือผ่านสคริปต์ที่แนบมาในโปรเจกต์ (ทำซ้ำ/อัตโนมัติได้ เหมาะกับการออกเวอร์ชันใหม่บ่อยๆ) ทั้งสองวิธีให้ผลลัพธ์แบบเดียวกัน คือไฟล์ `.msixbundle` ที่เซ็นด้วยใบรับรองของคุณเอง

#### แบบที่ 1 — ผ่านหน้าต่าง Visual Studio

1. คลิกขวาที่โปรเจกต์ **ClaudeUsage** → **Publish → Create App Packages…**
2. เลือก **Sideloading** (แจกจ่ายเอง) หรือ **Microsoft Store**
3. สร้าง/เลือกใบรับรองเซ็นแพ็กเกจใหม่ตามที่ตัวช่วยแนะนำ
4. เลือกสถาปัตยกรรมเป้าหมาย (x64 / x86 / ARM64) แล้วกด **Create**
5. จะได้ไฟล์ `.msixbundle` พร้อมสคริปต์ `Add-AppxPackage.ps1` ในโฟลเดอร์ผลลัพธ์

#### แบบที่ 2 — ผ่านสคริปต์ (`scripts/`)

ต้องรันบนเครื่องที่ติดตั้ง **Visual Studio 2022** (หรือ Build Tools for Visual Studio) ไว้แล้ว เพราะสคริปต์เรียกใช้ MSBuild ของ Visual Studio เบื้องหลัง — เปิด PowerShell ที่ root ของโปรเจกต์แล้วรัน:

```powershell
# 1) สร้างใบรับรองสำหรับเซ็นแพ็กเกจ (ทำครั้งเดียว เก็บไฟล์ certs\ClaudeUsage.pfx ไว้ให้ปลอดภัย)
.\scripts\New-PackagingCertificate.ps1

# 2) Build และเซ็นแพ็กเกจ MSIX ด้วยใบรับรองที่เพิ่งสร้าง
.\scripts\Build-MsixPackage.ps1 -Platform x64
```

ผลลัพธ์จะอยู่ในโฟลเดอร์ `dist\` — ไฟล์ `.msixbundle` คือไฟล์ติดตั้งที่ต้องส่งให้ผู้ใช้ ส่วนไฟล์ `certs\ClaudeUsage.cer` (ใบรับรองสาธารณะ ไม่ใช่ `.pfx`) ต้องส่งไปด้วยเพื่อให้เครื่องปลายทางเชื่อถือลายเซ็น

> เก็บไฟล์ `certs\ClaudeUsage.pfx` เป็นความลับเสมอ — เป็นกุญแจที่ใช้เซ็นแพ็กเกจ ห้าม commit ขึ้น Git (มีอยู่ใน `.gitignore` ให้แล้ว) ส่วน `.cer` เป็นใบรับรองสาธารณะ ส่งให้ผู้ใช้ปลายทางได้ตามปกติ

#### การติดตั้งบนเครื่องปลายทาง

ให้ผู้รับไฟล์ (`.msixbundle` + `.cer`) เปิด PowerShell ในโฟลเดอร์ที่มีทั้งสองไฟล์ แล้วรัน:

```powershell
.\Install-ClaudeUsage.ps1 -PackagePath .\ClaudeUsage_1.0.0.0_x64.msixbundle -CertificatePath .\ClaudeUsage.cer
```

(คัดลอกไฟล์ `scripts\Install-ClaudeUsage.ps1` ไปให้ผู้รับด้วย หรือจะติดตั้งด้วยมือตามขั้นตอนนี้ก็ได้: ดับเบิลคลิกไฟล์ `.cer` → Install Certificate → เลือก **Local Machine** หรือ **Current User** → Place all certificates in the following store → **Trusted People** จากนั้นดับเบิลคลิกไฟล์ `.msixbundle` เพื่อติดตั้ง)

> หากเครื่องปลายทางไม่เคยติดตั้งแอปแบบ sideload มาก่อน อาจต้องเปิด **Developer Mode** ก่อน (*Settings → Privacy & security → For developers*) ไม่เช่นนั้น `Add-AppxPackage` จะล้มเหลวแม้ใบรับรองจะถูกต้องแล้วก็ตาม

#### แบบที่ 3 — ทำเป็นไฟล์ `.exe` เดียวจบ (ไม่ต้องรู้จัก PowerShell เลย)

ทำไมไม่ทำไฟล์ `.exe` ให้เลย? — เพราะ ClaudeUsage เป็นแอปแบบ MSIX (จำเป็นต่อการเก็บ API Key อย่างปลอดภัย, การแจ้งเตือน, และการเริ่มพร้อม Windows ให้ทำงานถูกต้อง) ซึ่งไม่ใช่ .exe ธรรมดา แต่ **ห่อมันด้วยตัวติดตั้งแบบ .exe ได้** เพื่อให้ผู้ใช้ปลายทางเห็นแค่ไฟล์เดียว ไม่ต้องรู้จัก PowerShell/ใบรับรอง/MSIX เลย — โปรเจกต์นี้เตรียมสคริปต์ไว้ให้แล้วที่ `installer/ClaudeUsage.iss` (ใช้โปรแกรม [Inno Setup](https://jrsoftware.org/isinfo.php) ฟรี ~10MB)

บนเครื่องที่จะ **สร้าง** ตัวติดตั้ง (ต้องมี Visual Studio + ติดตั้ง Inno Setup 6 เพิ่ม):

```powershell
.\scripts\New-PackagingCertificate.ps1     # ครั้งเดียว
.\scripts\Build-Installer.ps1 -BuildBundle  # build MSIX แล้วห่อเป็น .exe ให้อัตโนมัติ
```

จะได้ไฟล์ **`dist\ClaudeUsageSetup.exe`** ไฟล์เดียว — ส่งไฟล์นี้ไฟล์เดียวให้ใครก็ได้ เขาแค่ดับเบิลคลิก กด Next ไปเรื่อยๆ แล้วก็ใช้งานได้เลย (ตัวติดตั้งจะเชื่อถือใบรับรอง เปิดการอนุญาต sideload และติดตั้งแอปให้อัตโนมัติทั้งหมด รวมถึงมีตัวถอนการติดตั้งใน *Apps & features* ให้ด้วย)

> ไอคอนแอปในเวอร์ชันนี้เป็นไอคอนตัวอย่าง (placeholder) — ควรเปลี่ยนไฟล์ในโฟลเดอร์ `Assets/` เป็นไอคอนแบรนด์จริงก่อนแจกจ่าย

## 4. เริ่มต้นใช้งานครั้งแรก

เมื่อเปิดแอปครั้งแรก ระบบจะอยู่ใน **Demo Mode** โดยอัตโนมัติ

**เชื่อมต่อกับข้อมูลจริง:**

1. กดไอคอนรูปเฟือง ⚙ ที่มุมขวาบนเพื่อเปิด Settings
2. ในส่วน API Configuration ปิดสวิตช์ **Demo Mode**
3. กรอก **API Endpoint** และ **API Key**
4. กด **Test Connection** เพื่อตรวจสอบ
5. กด **Save**

> **ข้อควรทราบ:** ปัจจุบัน Anthropic ยังไม่เปิดให้บริการ public API สำหรับดึงข้อมูลการใช้งาน/บิลลิ่งของผู้ใช้แต่ละคนโดยตรง ช่อง "API Endpoint" จึงหมายถึง endpoint ของระบบพร็อกซี/เกตเวย์ที่คุณจัดทำขึ้นเอง ซึ่งต้องคืนค่าข้อมูลตามรูปแบบ JSON ที่กำหนดไว้ในไฟล์ตัวอย่าง `src/ClaudeUsage/appsettings.sample.json` หากยังไม่มี endpoint ลักษณะนี้ ใช้ Demo Mode ต่อไปได้อย่างปลอดภัย

## 5. ภาพรวมหน้าจอหลัก

หน้าต่างหลักปรับขนาดได้อิสระ ส่วนต่างๆ จะแสดง/ซ่อนอัตโนมัติตามความกว้างหน้าต่าง (เล็ก/กลาง/ใหญ่)

- **การใช้งานวันนี้ (Today)** — เปอร์เซ็นต์การใช้งานเทียบโควตารายวัน + Requests / Tokens / Cost สีแถบเปลี่ยนตามระดับ: ปกติ (0–50%), ปานกลาง (51–75%), เตือน (76–90%), วิกฤต (91%+)
- **การใช้งานแยกตามโมเดล (Model Usage)** — สัดส่วนโทเคนต่อโมเดล (แสดงเมื่อกว้าง ≥ ~380px)
- **ประวัติการใช้งาน (Usage History)** — กราฟแนวโน้ม เลือกช่วง 24H / 7D / 30D (แสดงเมื่อกว้าง ≥ ~560px)
- **ค่าใช้จ่ายโดยประมาณ (Estimated Cost)** — วันนี้ / เดือนนี้สะสม / คาดการณ์สิ้นเดือน พร้อม % เปลี่ยนแปลงจากเดือนก่อน
- **สถานะการเชื่อมต่อ (API Status)** — จุดสีบอกสถานะ พร้อมเวลาที่อัปเดตล่าสุด และแบนเนอร์ + ปุ่ม Retry เมื่อดึงข้อมูลไม่สำเร็จ

ปุ่มมุมขวาบน: **↻** รีเฟรชทันที (หน่วง 2 วินาทีกันกดรัว), **⚙** เปิด Settings

## 6. การตั้งค่า

**การเชื่อมต่อ API** — Demo Mode, API Endpoint, API Key (เก็บใน Windows Credential Locker เท่านั้น ไม่เป็นข้อความธรรมดา), ปุ่ม Test Connection / Clear

**รูปลักษณ์ (Appearance)** — ธีม (ระบบ/สว่าง/มืด), ความโปร่งใส Mica/Acrylic, เปิด/ปิดอนิเมชัน, โหมดกระชับ (Compact Mode)

**การรีเฟรช** — ความถี่อัตโนมัติ: 30 วินาที / 1 นาที / 5 นาที (ค่าเริ่มต้น) / 15 นาที / ปิด, โควตาโทเคนต่อวัน (Daily Token Limit)

**การแจ้งเตือน** — เปิด/ปิดทั้งหมด, เลือกระดับแจ้งเตือนได้หลายระดับ: 50% / 70% / 80% / 90% / 95%

**การเริ่มต้นระบบและขั้นสูง** — เริ่มแอปพร้อม Windows, Verbose Logging (สำหรับแก้ปัญหาเท่านั้น)

อย่าลืมกด **Save** ทุกครั้งหลังแก้ไข

## 7. ไอคอนถาดระบบ

แอปจะอยู่ในถาดระบบ (System Tray) ตลอดเวลาที่เปิดใช้งาน การกดปุ่ม X ที่หน้าต่างหลักเป็นการซ่อนลงถาดระบบเท่านั้น **ไม่ได้ปิดแอป**

คลิกขวาที่ไอคอนเพื่อเปิดเมนู:

| รายการเมนู | หน้าที่ |
|---|---|
| Open Widget | เปิด/นำหน้าต่างหลักขึ้นมาด้านหน้า |
| Refresh | รีเฟรชข้อมูลทันที |
| Settings | เปิดหน้าต่างการตั้งค่า |
| Pause Auto Refresh | หยุด/เริ่มการรีเฟรชอัตโนมัติชั่วคราว |
| Exit | ปิดแอปอย่างสมบูรณ์ (ตัวเลือกเดียวที่ปิดแอปจริง) |

## 8. การแจ้งเตือน

เมื่อเปอร์เซ็นต์การใช้งานถึงระดับที่ตั้งไว้ แอปแจ้งเตือนผ่าน Windows Notification เพียงครั้งเดียวต่อระดับต่อวัน และแจ้งเตือนอีกครั้งเมื่อการเชื่อมต่อกลับมาใช้งานได้หลังมีปัญหา ปิดได้ที่ **Settings → Notifications**

## 9. แก้ไขปัญหา

| อาการ | วิธีแก้ไข |
|---|---|
| ขึ้นสถานะ Unauthorized | ตรวจสอบ API Key — กด Clear แล้วกรอกใหม่ จากนั้น Test Connection |
| ขึ้นสถานะ Rate Limited | endpoint จำกัดจำนวนคำขอชั่วคราว แอปจะลองใหม่อัตโนมัติแบบเว้นระยะเพิ่มขึ้น |
| ขึ้นสถานะ Connection Error / Offline | ตรวจสอบอินเทอร์เน็ต/endpoint ระหว่างนี้แอปแสดงข้อมูลล่าสุดที่บันทึกไว้แทน |
| ยังไม่มี endpoint จริง | เปิด Demo Mode ไว้ก่อนได้อย่างปลอดภัย |
| Build ไม่ผ่านใน Visual Studio | ตรวจสอบเวอร์ชันแพ็กเกจ NuGet (Windows App SDK ฯลฯ) แล้ว Restore ใหม่ |
| ต้องการล้างข้อมูล/ตั้งค่าทั้งหมด | ปิดแอปให้สมบูรณ์ (Exit) แล้วลบโฟลเดอร์ที่ `%LocalAppData%\Packages\<ชื่อแพ็กเกจ>\LocalState` |

## 10. คำถามที่พบบ่อย

ส่งไปยัง endpoint ที่คุณกำหนดเองใน Settings เท่านั้น เมื่อเปิด Demo Mode จะไม่มีการส่งข้อมูลออกจากเครื่องเลย

**API Key ปลอดภัยแค่ไหน?**
เก็บด้วย Windows Credential Locker (เข้ารหัสโดยระบบปฏิบัติการ) ไม่เคยถูกบันทึกเป็นไฟล์ข้อความธรรมดาหรือปรากฏใน log

**แอปกินทรัพยากรเครื่องมากไหม?**
ออกแบบให้เบา ดึงข้อมูลตามรอบเวลาที่ตั้งไว้เท่านั้น (ค่าเริ่มต้นทุก 5 นาที) ไม่เรียก API ถี่เกินจำเป็น

**ใช้ได้กับ Windows 10 หรือไม่?**
ใช้ได้ตั้งแต่เวอร์ชัน 1809 (build 17763) ขึ้นไป แต่ประสบการณ์ Mica/Fluent Design เต็มรูปแบบจะเห็นผลชัดเจนที่สุดบน Windows 11
